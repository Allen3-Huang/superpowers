## 審查清單

**程式碼品質：**
- 關注點是否有清晰的分離？
- 是否有適當的錯誤處理？
- 型別安全（如適用）？
- 是否遵循 DRY 原則？
- 是否處理了邊緣情況？

**架構：**
- 設計決策是否合理？
- 是否考慮了可擴展性？
- 效能影響？
- 安全顧慮？

**測試：**
- 測試是否真正測試邏輯（而非模擬）？
- 是否涵蓋了邊緣情況？
- 在需要的地方是否有整合測試？
- 所有測試是否通過？

**需求：**
- 是否滿足所有計劃需求？
- 實作是否符合規格？
- 是否有範圍蔓延？
- 是否記錄了破壞性更改？

**生產就緒程度：**
- 遷移策略（如有結構描述更改）？
- 是否考慮了向後相容性？
- 文件是否完整？
- 是否沒有明顯的錯誤？

## 關鍵規則

**要做：**
- 依實際嚴重程度分類（並非所有事情都是嚴重）
- 具體說明（檔案：行號，而非含糊）
- 解釋為什麼問題重要
- 承認優點
- 給出明確的結論

**不要做：**
- 未經檢查就說「看起來不錯」
- 將細節問題標記為嚴重
- 對未審查的程式碼提供回饋
- 含糊其辭（「改進錯誤處理」）
- 迴避給出明確結論
